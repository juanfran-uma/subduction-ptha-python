6. The input file

Step 6 gathers everything steps 1 to 5 found, plus a few values from the literature, into one JSON file: inputs/input_<zone>_scratch.json. It is the only thing the engine (step 7) reads, apart from the saved mesh, so it is also where a run can be changed by hand. This page lists every key.

At a glance

derived

computed from public data by steps 1 to 5: the contours, the mesh, the convergence and its profiles, the observed earthquakes.

declared

read from Berryman et al. (2015), the literature PTHA18 cites: coupling, b-value, largest observed magnitude.

setting

PTHA18's own configuration: magnitude range, tree resolution, Gutenberg-Richter shapes and weights, percentile settings.

Keys that start with _ are notes for people; the engine never reads them.

Step 6 never overwrites an edited file

Important when you re-runIf inputs/input_<zone>_scratch.json already exists, step 6 leaves it alone and prints already exists, NOT overwriting it. This keeps your hand edits when you re-run the whole pipeline with step_total.py. The other side of it: a change you make before step 6 (a new width in step 2, a convergence override in step 3, a new GCMT selection) does not reach the engine until you rebuild the file with steps/step6_write_input.py --force (or delete it).
python kermadectonga2/steps/step6_write_input.py --force   # rebuild from steps 1-5, discarding hand edits

Which to use, and what to re-run after each kind of change: Change a setting, re-run.

Keys that depend on the options

Some blocks are written only when a generate option asks for them. The defaults above are the ones without these options.

See variable shear modulus.
Optional keys the engine reads but step 6 does not writefor hand edits
  • rates.computational_increment: step of the magnitude grid on which every branch curve is tabulated. Default 0.02, PTHA18's value.
  • rates.maximum_allowed_mw_max: cap on Mw_max. Default 9.6 for thrust zones, 9.0 for normal-fault (rake -90) zones.
  • rates.mw_observation_error_halfwidth: if set, LEVEL 3 also computes weights that allow for a uniform error of +/- this value on the GCMT magnitudes. They are written to the posterior_prob_with_Mw_error column only; no rate uses them. Not set by step 6, so that column equals posterior_prob.
  • percentiles.threshold_Mw can be removed: the default is every 0.1 from Mmin to Mmax.
  • geometry.mode other than shapefile and mesh_file: planar (lon0, lat0, strike, dip, n_alongstrike, n_downdip, subfault_length, subfault_width, optional top_depth), official_grid and official_statistics. Step 8 uses official_statistics.
  • rates.conditional_probability_model also accepts "all_equal" (every scenario of a magnitude equally likely).
  • coupling.prior_type "explicit" takes values and probs; with it, uniform_range and spreadsheet_values are not needed.
  • A top-level "unsegmented" block (with optional geometry and rates sub-blocks) overrides settings of the whole-zone representation only, not of the segments.
  • Each entry of segments needs alongstrike_slice: [first, last] (columns) and, when LEVEL 3 is on, its own observed_seismicity (the engine refuses to credit a segment with the whole zone's earthquakes). Its convergence is not written: the engine averages the zone's convergent_slip_profile over the segment's own cells, unless the segment sets its own tectonic_convergence_mm_per_yr.

Where in the code: logic_tree/run_logic_tree.py build_source_representation(), build_parameter_axes(), main().
