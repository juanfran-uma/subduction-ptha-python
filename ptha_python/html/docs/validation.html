Validation

How the Python code is checked. The validation scripts compare whole results with the files PTHA18 published, zone by zone. Each check says what it compares, so a pass means what it says and no more.

At a glance

meshthe mesh built on PTHA18's own contours, with PTHA18's unit-source grid and statistics. It passes a zone when the dimensions are equal, the total area is within 0.2 percent and the mean dip within 0.05 degrees; the node offsets (median and maximum, in metres) are printed. It covers 14 zones by default (--zones picks others).the files in validation/ptha18_reference/. Any that are missing are downloaded from NCI the first time, so this check needs the network then

It covers 4 zones: puysegur2, kermadectonga2, kurilsjapan and southamerica.PTHA18's extracted trees (official_ptha_data/trees/) and inputs (inputs/input_ZONE.json)

Running the checks

Run the checks from the repository root. With no name, validate_against_ptha18.py runs the checks in the order of the table above. The gcmt check is skipped unless --ndk is given. A name runs one check.

python ptha_python/validation/validate_against_ptha18.py                     # all checks
python ptha_python/validation/validate_against_ptha18.py mesh                # one check
python ptha_python/validation/validate_against_ptha18.py gcmt --ndk kermadectonga2/data/gcmt

Each check prints one line per zone with its difference and a PASS or FAIL. The last line is the summary, for example SUMMARY: mesh PASS, .... The script exits with 1 if any check fails. A check whose extracted inputs are missing stops the whole script at that point with exit code 1, and prints the command that creates them (official_ptha_data/fetch_official_inputs.py with the zone names). On a copy without those files the default run therefore ends at engine, after mesh has passed: run mesh alone, or extract the inputs first.

The reference files

ptha_python/validation/ptha18_reference/ holds PTHA18's files that the checks read, copied from NCI's public server:

  • contours/SOURCEZONE_CONTOURS/: PTHA18's contour shapefiles, one per zone (51 zones, also in SOURCEZONE_CONTOURS.zip).
  • unit_source_grid/: PTHA18's unit-source grids, as shapefiles (16 zones).
  • nc/: PTHA18's unit-source statistics, one NetCDF file per zone (32 files).
  • events/: PTHA18's published uniform-slip event files, created by the events check when it first runs.

The branch tables and the published event files are not in the repository. official_ptha_data/fetch_official_inputs.py downloads PTHA18's saved session (1.34 GB, once) and extracts them. See The official PTHA18 run.

What is not validated

  • Zones PTHA18 never modelled. A zone built with --ptha false that PTHA18 did not model has no reference, so the checks say nothing about its numbers. Its code path is the same as for the modelled zones.
  • The options that are not PTHA18's procedure. --columns average, --cell-size strasser, --rupture-size local and the -edited column rules are not compared with PTHA18. None of them is the default. The default --convergence bird also differs from PTHA18 in the zones where PTHA18 used Griffin's traces (see Bird or Bird with Griffin).
  • The external mesh. --mesh-file is checked on one mesh only, the Alaska and Aleutians file.
  • The report's layout. The page is not tested. Its numbers are written from the CSV files of the steps, listed in Reading report.html.
  • The tsunami steps. This package stops at earthquake rates. The tsunami simulation and the hazard curves are not in it, so nothing here checks them.
