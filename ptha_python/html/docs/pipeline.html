The nine steps

A run is nine numbered scripts, plus the two lettered ones 7b and 7c, in a fixed order, and step_total.py runs them all. Each script reads the files the earlier ones wrote and writes its own. Steps 1 to 7 and step 9 are required; steps 7b, 7c and 8 are optional. This page lists what each step reads and writes, and how a run goes from start to report.

The flow

What each step reads and writes

Paths are inside the generated folder, and ZONE is the zone name (for example kermadectonga2). A step stops with a message that names the step to run first when a file it needs is missing.

step_total.py: all the steps at once

step_total.py does no work of its own. It starts each step script as a separate program, in the order of the table, so the result is the same as running them by hand. It prints >>> stepN_name.py before each step and Done in N min. See FOLDER/report.html at the end, and then appends the command line, the date and the run time to RUN.html.

  • Required steps (1 to 7 and 9): the first one that fails stops the run with its exit code and the advice to fix the error and run again.
  • Optional steps (7b, 7c, 8): a failure is printed and the run goes on to step 9, which writes the report without the section of the failed step.
  • --skip-official leaves out step 8. --skip-hs leaves out 7b and 7c. Step 7c is also left out, with a message, when the folder was made with --variable-mu off.
  • --auto-clip passes --auto-clip to step 1 and --force to step 6, so the input file is rebuilt and a hand edit of it is lost. --download-official-hs-vaus passes --download-hs to step 8.

Every flag is described, with its effect, in Options, files, columns.

What a finished run gives

After step 9 the folder holds the numbers of the run in three places. The report shows them with their figures. The CSV files in outputs/ hold them for other tools, with columns listed on Options, files, columns. The input file keeps the values the run was given, so a run can be read back.

  • The geometry: the number of cells, their total area and mean dip (step 2, in the report and in the README).
  • The convergence: one value for each column of cells (step 3).
  • The branches: one row per branch with its prior and posterior weight (step 7).
  • The rates: the mean rate and the percentiles, for each magnitude (step 7).

When a step fails

step_total.py stops at the first required step that fails, and prints which step it was. Fix the error the step printed, then either run step_total.py again (the earlier steps are repeated, which is harmless because the downloads are kept) or run the remaining steps one at a time, starting with the failed one. The optional steps do not stop the run: their failure is printed and the report is written without their section.

The common causes, with their fixes, are on Troubleshooting.

Time and shortcuts

The time of a run depends on the zone, its options and the machine, and step_total.py prints the total time at the end. In the reference runs, with step 8 skipped and the data already downloaded, the whole run took between 2.1 and 4.6 minutes for meshes of 26 to 312 unit sources (the table is on Quick start). The first run of a folder downloads its data, so it takes longer than a re-run. Four options shorten a run, each at a cost. The last two are flags of step 7b itself, given when that step is run on its own, for example python NAME/steps/step7b_stochastic_slip.py --max-fields-per-mw 50:

  • --skip-official skips step 8, which needs R, and the comparison with PTHA18 that it feeds.
  • --skip-hs skips the optional steps 7b and 7c.
  • --max-placements-per-mw and --max-fields-per-mw cap the number of heterogeneous-slip fields of step 7b. The result is faster and less exact.
