Troubleshooting

The messages a run can print, what each one means and what to do, grouped by the step that prints it. Every required step stops with a message instead of passing a bad result on. step_total.py stops at the first required step that fails and names it. An optional step that fails is reported, and the run goes on.

Step 1: the SLAB data and the contours

MessageWhat to do
ScienceBase is behind Cloudflare's bot check right now (HTTP 403 ...) SLAB2.0 zones, name ending in '2'the download site blocks scripts, and retrying does not always clear it. The message prints the item link for the region, a search link and the folder to save the file into. Open the item in a normal browser, download the zip, extract the single <region>_slab2_dep_*.grd file into that folder, and run the step again. Every SLAB2.0 item can be searched at sciencebase.gov.
could not download SLAB1.0 grid for region '...' followed by an HTTP error (403 or 404) SLAB1.0 zones, name without a trailing '2'the message prints the direct download address, the page that lists the SLAB1.0 regions, and the file name and folders to save into (the zone's own folder is checked first). For the regions cal, car, cam, hel, mak, png and puy the USGS server has no such file (it answers AccessDenied, as for any missing name): use the zone's 2 version, or put a grid you have into FOLDER/data/slab1/. For the other regions a 403 can be a block on USGS's side: download the file in a browser, save it with the exact name, and run the step again. See Zones you can run.

Delete data/slab2/_<region>_sciencebase_item.zip in the folder and run the step again. If the message repeats, put the single <region>_slab2_dep_*.grd file into data/slab2/ by hand.

the trench-like edge vanished after end trimmingthe end trimming removed the whole up-dip edge. Widen or remove --clip, and check in the step 1 figure that the region contains the zone's trench.

step 1 cannot build a valid contour set:, followed by the reasonsthe reasons are lines such as levels [...] km below trench are not in the raster at all, the N km level is a closed loop, ... comes in pieces, ... only N km long against M km for the level above it and ... runs along the edge of the SLAB model. See the checks. Look at the step 1 figure. A --clip window or a cutoff deeper than the SLAB model is a common cause.
trench_ends: every level must be one open line before the cut, or trench_ends ...: the cut could not be applied (...) the six zones cut at Berryman's end pointsthe zone is cut along the down-dip lines through its two end points, and the raster or a --clip window does not allow it (a level in pieces, an end point outside the window). Remove --clip or widen it so that it holds both end points, and look at the step 1 figure.
clean ends: NOT applied (...)a cut line had no clean crossing with a contour, so the raw ends are kept. Check the ends in the step 1 figure and the mesh figures of step 2.

For a PTHA18 zone, try --convergence bird-griffin.

The mesh extends onto the next subduction zone. Cut the tail with step_total.py --auto-clip or an explicit --clip (recipe). Nothing is trimmed by step 3.
no *.ndk files in ... (step 5)step 4 has not run, or its files were deleted. Run step 4.

run_logic_tree.py exited with code N (steps 7, 7c and 8)the engine stopped. The message above it is the cause: a Python traceback ending in a ValueError from the input JSON (for example alongstrike_slice ... outside 1..N, conditional_probability_model ... not recognized or unknown coupling prior_type) after a hand edit. Run step 6 with --force to restore a valid file.
observation threshold ... is below Mw_min ... (step 7)the input JSON has an observed_seismicity.threshold_Mw below Mw_min. PTHA18 puts the half-bin offset on Mw_min (7.15), so set both to the same value.
update_logic_tree_weights_with_data is true but no 'observed_seismicity' block was given (step 7)the input JSON asks for the LEVEL 3 update but has no catalogue. Run step 6 again with --force, or set the flag to false.
Mw_max_anchor must be a pair or 'derive', got ... (step 7)a hand edit of Mw_max_anchor. Use "derive", which step 6 writes, or two numbers: the lowest and highest Mw max of the range, for example [8.8, 9.6].
unknown edge correction mode ... (step 7)edge_correction.mode must be fit (what step 6 writes), fixed, inherit or off.
skipped (HTTP Error 404: Not Found) (step 4)nothing: the monthly file is not on the server yet, which is normal for the most recent months. The subset uses only the window from 1 January 1976 to 1 March 2017.
could not download any part of the GCMT cataloguethe GCMT server could not be reached. Download the NDK files by hand into the folder's data/gcmt/. The message gives the path.
... already exists, NOT overwriting it. (step 6)not an error: the existing input JSON is kept, so your hand edits survive. Run step 6 with --force to rebuild it after changing steps 1 to 5 (Change a setting, re-run).
could not find ... in ... has it been renamed or removed? (step 6)step 6 reads some constants of step 2 by name. Restore the constant in step 2.
... has N values but the source has M along-strike columnsthe mesh has a different number of columns from the one the convergence profile was made for. Run steps 3 and 6 again (step 6 with --force), or remove the profiles from the JSON.
convergence_profile has no positive value: no tectonic moment on this sourceBird gives no convergence anywhere on the zone. Check the zone, or set a constant convergence in step 3.
mesh: step 2's saved grid does not match this input's meshing fieldsnot an error: a meshing field of the input JSON was changed, so the engine meshes again with the new value.
WARNING segment ...: its geometry cannot host Berryman's floor Mw ... (step 6) --segmented truethe segment is too small for the largest magnitude Berryman gives it, so it keeps its own catalogue value. This usually means a tail that belongs to a neighbouring zone (in kurilsjapan, the Izu-Bonin tail). Check the plate-boundary warning in step 3 and the report.

Segmented runs (--segmented true)

Message or behaviourWhat it means, and what to do
a single segment here (berryman), so there is nothing to segment; step 6 will run this zone unsegmented. (step 5)not an error. Berryman et al. (2015) do not divide this zone, or only one of its segments lies on this mesh. The run is unsegmented: the report says UNSEGMENTED RUN and has no LEVEL 0 section. With --segment-boundaries bird the same happens where Bird has one plate pair.
... gets no column of this mesh (its trench lies beyond it): left out (segmentation)not an error. A Berryman segment lies past the end of this mesh, so it is left out of the run.
--auto-clip: --auto-clip needs step 3's plate-boundary finding, and FOLDER/data/plate_boundary_change.json is not there. (step 1)run steps 1 to 3 once, or a full run, and then step_total.py --auto-clip. If step 3 ran and found no change, there is nothing to cut.
--auto-clip: step 3 did flag a plate-boundary change here, but a lon/lat box cannot separate the flagged columns ... (step 1)the arc doubles back on itself, so a box cannot cut the tail. Give an explicit --clip LON_MIN,LON_MAX,LAT_MIN,LAT_MAX in a new folder; the message lists the flagged columns.
segment '...': edge_correction mode 'fit' is not PTHA18's method on a segment; use 'inherit' (step 7)the segments block of the input JSON was edited by hand. A segment takes the zone's edge multiplier, as in PTHA18. Set its edge_correction back to {"mode": "inherit"}, which step 6 writes.
segment '...' inherits the whole zone's observed_seismicity, which would credit it with earthquakes that happened outside it (step 7)a segment was written without its own earthquakes. Run step 6 again with --force, which gives each segment its own GCMT events, or give the segment an observed_seismicity block.
step 5 prints also in a neighbouring segmentexpected. An earthquake near a boundary passes the selection rule of both neighbouring segments, so it is counted in both. The segments' events can add up to more than the zone's events.
the percentile band does not surround the solid line in the rate chartexpected. On a segmented run the band belongs to the whole zone (the LEVEL 0 mix), while the solid line is the unsegmented branch. See Reading report.html.
No official segmented run to compare with (report, LEVEL 0)step 8 has not run, or PTHA18 did not segment this zone. Step 8 builds PTHA18's segmented run only for the zones that have segment rows in sourcezone_parameters.csv.
step 8 asks for Rscript even though the trees were extracted beforeit always starts R, so R is needed even then. Install R, or run with --skip-official.
