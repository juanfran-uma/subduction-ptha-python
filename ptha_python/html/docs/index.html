ptha_python: PTHA18 earthquake sources from public data

One command builds a complete earthquake source model for a subduction zone, in the way the Australian tsunami hazard assessment PTHA18 built its own: the fault surface cut into cells, how fast the plates converge, which earthquakes have happened on the interface, and how often each possible earthquake is expected. It uses public data only. Where PTHA18 published its own files, the package checks itself against them.

At a glance

Four data sets go in on the left: three public files and the literature values of Berryman et al. (2015). The numbered steps turn them into a source model on the right. By default (--ptha false), PTHA18's own published files (bottom) are used only to check the result, never to build it.

What it does, in five points

  1. Step 1 downloads the depth of the sinking plate (USGS SLAB) and draws depth lines every 5 km, measured from the nearby trench, down to the depth where large earthquakes stop. Where the data ends crookedly, it cuts the zone's ends square. Step 1, clean ends
  2. Step 2 cuts that surface into cells of about 50 km (the unit sources) with rptha's method. With the default --discretizer optimal the mesh is repaired only if a cell is folded, collapsed or overlapping. Step 2, optimal, lm and mid
  3. Step 3 reads how fast the plates converge under each column of cells from Bird's (2003) plate model. Steps 4 and 5 pick the earthquakes of the Global CMT catalogue that happened on this interface. Step 3, steps 4-5
  4. Steps 6 and 7 put everything in one input file and run the logic tree: 32,000 combinations of coupling, b-value, maximum magnitude and the shape of the Gutenberg-Richter law, each balanced against the plate motion, re-weighted by the observed earthquakes, and summarised into rates with uncertainty. Step 6, step 7
  5. Step 9 writes report.html with every number and figure, including the mesh on a real map. Step 8 (optional, needs R) runs PTHA18's own inputs through the same engine, so the two can be compared. Step 8, reading the report, data provenance

A complete first run

After git clone, create a virtual environment with Python 3.13 and run pip install -r requirements.txt (the exact commands for Windows, macOS and Linux are in the Quick start). Then, from the repository root, generate a folder for a zone and run all its steps. The Quick start also explains each option, what needs the network, and has a command builder.

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2
python kermadectonga2/steps/step_total.py --skip-official     # steps 1-9; step 8 needs R

Then open kermadectonga2/report.html in a browser. In the reference runs of this package (meshes of 26 to 312 unit sources, step 8 skipped, the data already downloaded) a complete run took between 2.1 and 4.6 minutes. The first run also downloads the GCMT catalogue (about 30 MB), and a zone whose SLAB grid is not shipped with the package downloads that too.

How far to trust the results

checked against PTHA18

  • Given PTHA18's own contours, the mesh is compared with PTHA18's mesh.
  • Given PTHA18's own inputs, the logic tree is run by the same engine as this package, and its branches and rates are compared with PTHA18's published tables.
  • The earthquake selection and the plate convergence are compared with PTHA18's own lists and values.

Details: Validation.

different by design

  • The contours come from SLAB automatically, while PTHA18 edited its own by hand, so meshes differ by a few kilometres, most at the ends of a zone.
  • Where PTHA18 extended a zone beyond the SLAB data by hand, this package does not invent geometry.
  • Options marked not PTHA18's procedure in the reference change the calculation on purpose. They are off by default.
