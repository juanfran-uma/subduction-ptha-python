Rupture size (--rupture-size)

An earthquake scenario is a block of unit sources that slip by the same amount. Its size is set by its magnitude through the scaling relation of Strasser et al. (2010). The question this page answers is how many unit sources such a block gets. The default, rptha, uses one block size per magnitude, worked out from the zone's mean cell size. The option local sizes every block from the real area of the cells it covers, and corrects each rupture's weight for how many ruptures overlap it. Use local when the cells of a mesh differ a lot in size.

Why the size rule matters

PTHA18's unit sources are about 50 x 50 km everywhere on its meshes, so one block size works for every place of the zone: a block of, say, 2 cells along the trench by 1 cell down the slope covers about the right area at every position. rptha, the R package behind PTHA18, works the same way. It computes one block of cells per magnitude from the zone's mean cell length and width, and slides that block over the whole mesh.

That assumption breaks when the cells differ a lot in size. In calabria2, for example, the cell areas run from about 377 to 4,042 km2, because the trench is an arc and its far edge is much shorter than its near edge. The same block is then much too large in one place and much too small in another. The slip of each rupture is still set from its real area, so the slip of a given magnitude spreads over a wide range instead of being close to the scaling relation's value everywhere.

What local does

For every cell where a rupture can start, and for each number of rows, the program finds the number of columns whose summed real area is closest to the target area from the scaling relation. Among these candidate blocks it keeps the one with the smallest combined error in area and in aspect ratio (length to width), using the same two criteria as rptha, but measured with the real kilometres of those cells. Then:

  • A placement whose best block would need cells beyond the far edge of the mesh is skipped, just as rptha skips a placement where its block does not fit.
  • A rupture longer than the whole zone becomes the full length of the zone at the first placement (the start of the mesh), with the number of rows chosen by area alone, as in rptha. Placements further along that would need the same block are skipped because they do not fit.
  • Every cell must belong to at least one rupture of every magnitude (rptha's blocks cover every cell, because its last placement ends flush with the edge). Skipping placements can leave cells uncovered, mostly next to the far edges, so each uncovered cell gets one more block: of all blocks that contain it and fit on the mesh, the one with the smallest combined area and aspect error.
  • The slip of each rupture is the moment of its magnitude divided by the rigidity and by its real area. This is the same formula as with rptha.

The result is one event for each placement, each with its own block size, instead of one block size per magnitude. On a regular mesh with equal cells the two rules give blocks of about the same area.

Not PTHA18's procedurePTHA18 and rptha use one block size per magnitude. With local the list of earthquakes is different from PTHA18's, event by event, even though each magnitude is sized to the same scaling relation. Use local to study a zone whose mesh has very uneven cells, and say so when you report the results.

Where in the code: pyptha/events.py _local_blocks(), called by get_all_earthquake_events_of_magnitude_Mw() and get_all_earthquake_events() with rupture_size=. The engine reads the setting from the input file (events.rupture_size, rptha when absent) in logic_tree/run_logic_tree.py, and step 7b and step 9 read it the same way.

The rupture-overlap correction, q

With local every cell starts one rupture. A part of the zone with small cells is therefore covered by more ruptures per square kilometre than a part with large cells. Each rupture has about the same weight in PTHA18's rule (its weight is proportional to its area times its convergence), so the places with small cells would collect more earthquakes for no tectonic reason. The two places have the same area and the same convergence, so the plates ask for the same rate in both. Only the way the mesh was drawn differs.

The fix is a factor q for each rupture:

qe = mean over the cells c of rupture e of ( 1 / number of ruptures of the same magnitude that contain c )

The engine multiplies the conditional probability of each rupture by its q, and then renormalises the probabilities of each magnitude so that they add up to 1. This is applied after whichever of the three conditional-probability models the input uses (area times convergent slip, which is the default; equal weights; or 1 over slip), and only with local. With rptha's blocks every interior cell is covered by the same number of ruptures, so q is the same for every interior rupture and the correction has no effect there.

q also changes the two ends of the zone. Fewer ruptures cover the first and last columns, so their q is larger, and they receive more weight. This does part of the job of the edge correction of LEVEL 4, which is still fitted afterwards on the corrected weights. The fitted edge multiplier is therefore usually smaller with local than with rptha on the same zone.

What it changesWhere the earthquakes of each magnitude happen, and so the slip and sea-floor uplift of every scenario. What it does not change is how many earthquakes of each magnitude happen per year, for the reason in the next section.

Where in the code: pyptha/events.py coverage_weights(); logic_tree/run_logic_tree.py, build_source_representation(), the block that starts if rupture_size == "local". The log prints the q range, for example (puysegur2, 26 cells) conditional probabilities x q (rupture overlap correction, q from 0.190 to 1.000). q is at most 1; it is 1 for a rupture none of whose cells is covered by another rupture of its magnitude.

What stays the same

The moment balance (LEVEL 2) adds up, for each magnitude, the weight times the slip times the area of its ruptures. Each rupture's slip is set so that its slip times its area times the rigidity is exactly the moment of its magnitude, and the weights of one magnitude add up to 1. That sum is therefore M0 divided by the rigidity, whatever the shapes of the ruptures and whatever their weights. The moment balance, and so the number of earthquakes of each magnitude per year, does not depend on the rupture rule.

The places do change. Changing where an earthquake of a magnitude happens changes the slip of each scenario, and through the slip the sea-floor deformation and the tsunami of each scenario. Scenarios with local are not PTHA18's scenarios, so the check against PTHA18's published rates (validation) applies to the default rule only.

How to use it

python ptha_python/generate.py calabria --zone calabria2 --folder calabria2 --ptha false --rupture-size local
python calabria2/steps/step_total.py --skip-hs

The option is set once, at generation time (--rupture-size {rptha,local}, default rptha); it is written into the input JSON by step 6 and read by steps 7, 7b and 9. Step 7b regenerates the FAUS ruptures with the same rule, so its HS and VAUS fields hang on the same parents. To check that a folder uses it:

  • In inputs/, the input JSON has "events": {"rupture_size": "local", ...}. Step 6 always writes the key ("rptha" by default); an input without it, such as a hand-written one, uses rptha's rule.
  • In the run log, the line n_events = 171 (rupture size: local) (the number is the zone's) and the q line conditional probabilities x q appear. With rptha the first line reads (rupture size: rptha) and there is no q line.
  • In report.html, the rupture section names the rule, and the rupture explorer shows each rupture with its own block.

Limits

  • No rupture is smaller than one cell. If the cells are larger than the target area of the smallest magnitude, the smallest ruptures are one cell and come out larger than their target area.
  • The heterogeneous-slip generator still assumes equal cells. Step 7b places its random slip fields on a footprint with one cell size. On a mesh with very uneven cells, its fields are less realistic than the rupture areas above. See HS and VAUS slip, equal cells assumed.
  • The cells themselves are not changed. q and the local blocks fix how ruptures are built from the cells. They do not make the cells more regular. The mesh rules are on step 2 and the discretizer page.
  • Local is an option, not PTHA18's procedure. The default is what PTHA18 used.
