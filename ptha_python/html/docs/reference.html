Your own runs

Options, files, columns

The single reference for the program: every option of generate.py with its default and its allowed values, every flag of step_total.py and of the individual steps, the constants at the top of each step script, the folder a run creates, what each script prints, its exit codes, and the columns of the output files. All commands are run from the repository root.

generate.py options

Every option is listed here. The defaults are the values used when the option is not given, so a command with only a region name is valid. Options marked not PTHA18's procedure change the calculation away from what PTHA18 did; they are described in full on their own pages.

Combinations the program refuses

generate.py checks these before it writes anything, and stops with a message (exit code 1).

  • --cell-size strasser needs --discretizer optimal and cannot be combined with --mesh-file. --cell-k must be positive.
  • --columns trench-edited and --columns average-edited need --discretizer optimal and --cell-size mean, and cannot be combined with --mesh-file.
  • --clip must have four numbers with the minimum below the maximum in both longitude and latitude.
  • --mesh-file must name a file that exists and reads as a structured quadrilateral mesh.
  • The region must match exactly one SLAB region, and with --ptha true the zone must be an unsegmented sourcename of sourcezone_parameters.csv.

Two combinations are not refused at generation but fail later. --variable-mu on needs step 7b: step_total.py --skip-hs skips step 7c as well, because 7c needs 7b's scenarios, and step 7c run alone stops if 7b's output is missing. A zone with no Berryman et al. (2015) mapping is accepted, with a note, and stops at step 1.

What --ptha reads

The default, --ptha false, keeps the public-data pipeline free of PTHA18's files. The only step that ever reads PTHA18's files is step 8, the official run, and it runs only when R and rptha are available.

ValueSteps 1 to 7 and 9Step 8 (official run)
--ptha false (default)read no PTHA18 or rptha file. The unit-source width is 50 km, the row count comes from the geometry, and the rigidity is 30 GPa with the Strasser scaling relation.runs PTHA18's official inputs through the same engine, as the comparison target.

The literature values in each folder's README (seismogenic cutoff, coupling, b-value and maximum observed magnitude) come from Berryman et al. (2015), through lib/berryman_params.py. The README lists the values the folder used.

step_total.py flags

The flags of the runner. It passes some of them on to the steps it runs.

FlagWhat it does
--skip-officialSkips step 8 without trying it. Use it when R with rptha is not installed.
--skip-hsSkips step 7b and step 7c.
--auto-clipRuns step 1 with --auto-clip and step 6 with --force. Step 1 cuts the along-strike columns that step 3 flagged as lying on a different plate boundary, using a window derived from the mesh. It needs steps 1 to 3 to have run once, because the finding comes from the mesh they produced. Step 6 rewrites the input file, so any hand edit to it is lost.
--download-official-hs-vausPasses --download-hs to step 8, which fetches PTHA18's published HS and VAUS catalogues for the zone from NCI THREDDS and compares step 7b's fields with them. The downloads can be large, and they only feed one section of the report.

Which steps stop the run: steps 1 to 7 and step 9 are required, so a failure there stops step_total.py. Step 7b, step 7c and step 8 are optional: a failure is printed and the run goes on, and the report then has no HS/VAUS or official-comparison section. Step 7c is also skipped, with a line saying so, when the folder was generated with --variable-mu off.

Every script starts with a banner of its name between two lines of =, prints indented progress lines, and ends with a line Next: stepN_name.py. The lines to look for:

Start with: the command of step 1.

Exit codes

  • Exit code 0: the script finished. This includes step 6 finding an existing input file, step 7c with --variable-mu off and no --force (it does nothing), and step 8 for a zone PTHA18 never modelled (it writes outputs_official_status.txt and does nothing else).
  • Exit code 1: the script stopped with a message (a missing file from an earlier step, a failed download, a bad option value) or with a Python traceback. The message is the last thing printed. Troubleshooting lists the messages.
  • Exit code 2: generate.py or a step was given an option it does not know, or a value outside the allowed ones.
  • step_total.py exits 1 when a required step fails, naming it, and exits 0 when the last step ends, even if an optional step failed on the way.

Some files live outside the folder:

  • The SLAB grid cached in ptha_python/data/slab2/ (or data/slab1/) is used without being copied into the folder. Nothing writes that shared folder automatically; a grid placed there by hand serves every folder of the region.
  • While step 7 and step 7c run, the engine writes to runs/python/RUN_NAME/ in the repository root, where RUN_NAME is the run_name of the input file (ZONE_scratch_NAME, with _variable_mu added for 7c). The step copies the results into outputs/ and then removes that staging folder.

  • Step 8 and fetch_official_inputs.py also write official_ptha_data/trees/, official_ptha_data/public_nc/, the saved session file, and inputs/ at the repository root.

Columns of the output files

The files of outputs/ with their columns in the order they are written. Rates are annual rates of exceedance: the mean rate of earthquakes of that magnitude or larger, per year. For a segmented run, a file that exists per representation also exists once per segment, with the segment name added to the file name (scenario_rates_kermadectonga2_tonga.csv).

What a segmented run adds

With --segmented true the folder has the same files as an unsegmented one, plus:

  • report_unsegmented.html, the report of the unsegmented branch on its own, linked from report.html.
  • In data/gcmt/, one subset file for each segment and segments.json.
  • In outputs/rate_curves.csv, one column for each segment, the union of the segments, and the source-zone mix.
  • One file per segment for the branches, scenario rates, conditional probabilities, integrated slip and the five per-source figures, plus scenario_rates_ZONE_source_zone.csv and exceedance_rate_percentiles_unsegmented.csv.
  • A segment column in outputs/exports/convergence_profile.csv and mesh_cells.csv.
  • outputs/segmentation.csv, with the weight of each representation: 0.5 for the unsegmented branch and 0.5 for the union of the segments; each segment row shows the weight of that union.
  • A LEVEL 0 section in report.html, with a map of the segments (figures/segments_map.png).

Known limits

  • The default settings follow PTHA18's procedure, but the geometry comes from SLAB, which PTHA18 edited by hand. Meshes can differ by a few kilometres, most at the ends of a zone (Clean ends).
  • Where PTHA18 extended a zone beyond the SLAB data by hand, this package does not extend it. The zone is cut or kept as the data allows.
  • Step 8 needs R with rptha, and downloads PTHA18's saved session, which is more than a gigabyte, once for the first zone that needs it. Without R, use --skip-official.
  • The SLAB depth grids are downloaded from the USGS hosts in step 1. A host can refuse the download with an HTTP 403 error, and some SLAB1.0 grids are not on the server at all. The step prints the link to download the file by hand. See Troubleshooting and Zones you can run.
  • The map in step 2 of the report loads its base tiles from the internet when the report is opened.
  • Options marked not PTHA18's procedure give results that cannot be compared event by event with PTHA18's files.
