Start

Quick start

Three steps: generate a folder for a zone, run it, open the report. Every command is run from the repository root, the folder that holds ptha_python/, rptha/, official_ptha_data/ and inputs_meshes/. This page goes from git clone to an open report.html: the installation, what needs the network, one complete first run with its run time, where the results land, what to look at, and a command builder for any combination of options.

At a glance

Install

Everything needed to go from an empty machine to a first run. Only the activation command of the virtual environment differs between systems.

  1. Get the code. Clone the repository and go into it. This folder is the repository root, and every command in this guide is run from there. 
    git clone <repository URL>
cd <the cloned folder>
    The folders that generate.py creates are listed in .gitignore, so a zone run never shows up in git status and is never committed by accident.
  2. Check Python. The code was written and run with Python 3.13; other versions were not tested. python --version must print 3.13.x. On Windows with several versions installed, py -3.13 picks the right one. On macOS and Linux the command may be python3 until the environment below is active.
  3. Create a virtual environment and install the packages of requirements.txt (numpy, scipy, pandas, matplotlib, shapely, geopandas, pyproj, netCDF4 and pillow; certifi, which step 4 uses, comes with pyproj). 
    py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
    If PowerShell refuses to run the activation script, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once and activate again.
    py -3.13 -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
    python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
    The prompt shows (.venv) when the environment is active. Activate it again in every new terminal; every python command below uses it.
  4. Check the install. python ptha_python/generate.py --help prints every option. A ModuleNotFoundError means the environment is not active or the pip install did not finish.

What needs the network

generate.py and the steps that are not in the table are offline. A file that is already on disk is never downloaded again, so only the first run of a zone downloads.

StepWhat is downloaded
1The SLAB depth grid of the region, only when it is not on disk. The SLAB2.0 grids of the regions cal, car, hel, ker, mak, png, puy and sum ship in ptha_python/data/slab2/, so a zone name that ends in 2 (kermadectonga2, puysegur2, calabria2) in one of those regions downloads nothing. Any other region, and every zone whose name does not end in 2 (SLAB1.0, for example cascadia or kermadectonga), is downloaded into the folder's data/slab2/ or data/slab1/: SLAB2.0 from ScienceBase (a zip of tens of MB), SLAB1.0 from earthquake.usgs.gov. A run with --mesh-file downloads nothing here.
4The GCMT catalogue, from the Lamont-Doherty server: one cumulative file of about 23 MB and one small file for every month since January 2021, about 30 MB in all. Months that are not yet published answer HTTP 404 and are skipped, which is normal.
8Only if it runs: PTHA18's saved session (1.34 GB, once) and the zone's tables from NCI. It also needs R with the rptha package, see below.
9Nothing is downloaded when the report is written. When report.html is opened in a browser, its maps load the Leaflet library from cdnjs.cloudflare.com and the Esri map tiles from server.arcgisonline.com, so the maps cannot draw offline.
R is needed only for step 8Step 8 builds PTHA18's own run so that the report can compare the two. It needs R, the R package rptha (the rptha/ folder of this repository holds only data files, not the package) and, on Windows, Rtools; the install commands are printed by step 8 itself when it cannot find Rscript. Without R, add --skip-official to the run command: step 8 is not tried, the other steps run as usual, and the report has no comparison section. If you do not add it and R is missing, step 8 prints "Rscript not found", the runner continues, and the result is the same. Step 8 also needs a zone that PTHA18 modelled; for any other zone it writes a one-line note and stops without an error.
If step 1 stops with a download error (HTTP 403)Either SLAB host can refuse a scripted download: ScienceBase (SLAB2.0) with a "Just a moment..." page, or earthquake.usgs.gov (SLAB1.0) with its own firewall. Retrying does not help. The error message of step 1 gives the exact link for your region and the folder to save the file into. Download it in a normal browser, put it in place, and run the step again. Details: Troubleshooting.

1. Generate a folder

Name the region and the zone. The zone names are listed in Zones you can run, and the regions with python ptha_python/list_regions.py. generate.py reads only local files and takes a second or two.

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2

The program prints the settings it chose, then writes the folder: twelve scripts in kermadectonga2/steps/ (the step scripts 1 to 9, with 7b and 7c, and step_total.py), a README.md with the settings and literature values of the run, and RUN.html. If --folder is not given, the folder is named after the region, in lower case with other characters replaced by underscores. Every option is listed in Options, files, columns; the recommended options for each zone are on Recipes.

All the options of generate.py. Only the region is required and every other option has a default. --zone is needed in practice whenever the region name matches more than one zone: kermadec alone stops with the choice between kermadectonga and kermadectonga2. The command builder below writes the command for you, and Options, files, columns describes each option in full.

2. Run the folder

One command runs all nine steps in order, each as its own program, and stops at the first required step that fails:

python kermadectonga2/steps/step_total.py --skip-official

The output names each step as it starts (>>> step1_fetch_slab2.py), the program prints its own progress below the name, and the last lines are Done in 3.3 min. See kermadectonga2/report.html.

What --skip-official does. It leaves out step 8, the only step that needs R and the only one that downloads PTHA18's files (1.34 GB). Step 8 is then not tried at all, the other steps run as usual, and the report has no comparison section. Use it whenever R with rptha is not installed, or when the comparison is not wanted. The other flags of the runner, --skip-hs, --auto-clip and --download-official-hs-vaus, are described in Options, files, columns.

Running a step again

Each step can also be run on its own, in order, when one step needs to be repeated after a change: for example python kermadectonga2/steps/step7_run.py. The steps read their inputs from the folder, so a later step sees what an earlier one wrote. The nine steps lists what each one reads and writes. Two things to know before repeating steps: step 6 keeps an existing input JSON, so a hand edit survives, unless it is run with --force; and step 7 replaces the whole outputs/ folder, so step 7b (and 7c) must be run again after it.

When step_total.py finishes, it appends its exact command, the date and the run time to RUN.html, so the folder records how it was run.

3. Open the report

Open kermadectonga2/report.html in a browser: double-click it in the file manager, or from the repository root use start kermadectonga2\report.html (Windows), open kermadectonga2/report.html (macOS) or xdg-open kermadectonga2/report.html (Linux). It holds every number and figure of the run, the mesh on a real map (the map needs an internet connection), and, when step 8 has run, the comparison with PTHA18's own run. The report is written for reading from top to bottom; Reading report.html explains each section.

Where the results are

Everything a run writes stays inside its folder, which is named by --folder.

kermadectonga2/
  report.html           the report (step 9); a segmented run also has report_unsegmented.html
  README.md, RUN.html   the settings of the run, and the commands used
  steps/                the 12 scripts
  inputs/               the input JSON of the engine, and geometry/ (the contours, or your mesh file)
  data/                 the SLAB grid if it was downloaded, the saved mesh, the plate convergence, gcmt/
  figures/              the geometry figures: trench and contours, mesh maps
  outputs/              the numbers: rate curves, percentiles, branches, scenario rates (CSV),
                        figures/, exports/ (the CSV files behind the report), hs_slip_fields/ ...
  outputs_official/     PTHA18's run, only if step 8 ran

What to look at first

  • The mesh: the cells should follow the trench and the plate interface without holes or folds. Step 2 prints whether it had to repair the mesh: with the default --discretizer optimal, a mesh is repaired only when a cell is broken.
  • The rate curve: the mean exceedance rate falls as the magnitude grows, with percentiles around it (outputs/exceedance_rate_percentiles.csv).
  • The branch table: outputs/logic_tree_branches_kermadectonga2.csv has one row per branch, 32,000 in the standard tree, with its prior and posterior weight.
  • The comparison, if step 8 ran: the area, mean dip and convergence of the mesh against PTHA18's.

    A segmented run
    
  
    The same zone can also be run split along strike, as LEVEL 0 of the logic tree. It is a separate folder, so both runs can be compared:
    
  
    python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_seg --segmented true
python kermadectonga2_seg/steps/step_total.py --skip-official
    
  
    The segmented folder adds report_unsegmented.html and a LEVEL 0 section to the report. What the split changes is on Segmented vs unsegmented.
    

    


    
  
    A run on your own mesh
    
  
    A quadrilateral mesh that you already have can replace the SLAB geometry: the unit sources are the cells of the file, used as given. The file has one line per unit source with twelve numbers, its four corners as longitude, latitude and depth, in order round the cell. The repository includes one such file, for the Alaska-Aleutians zone:
    
  
    python ptha_python/generate.py alaska --zone alaskaaleutians --mesh-file inputs_meshes/alaskaaleutians_quadrilateral_coors.dat --folder alaskaaleutians_mesh --ptha false --rupture-size local
python alaskaaleutians_mesh/steps/step_total.py --skip-official
    
  
    In this case step 1 has nothing to fetch and step 2 reads the file instead of cutting SLAB contours into cells. Steps 3 to 9 run as usual. --mesh-file cannot be combined with --cell-size strasser or with the -edited values of --columns, and --discretizer, --columns and --clip have no effect with it. --zone still matters: it selects the literature values and the plate convergence of the zone.
    
  
    The file is copied into the folder's inputs/geometry/, and its depth units are read automatically. The format, its checks and the difference from a SLAB mesh are on External mesh.
    

    


    
  
    Other zones
    
  
    Recipes gives, for each known zone, the command to generate and run it and the settings that matter for that zone. A zone whose mesh is unusual (a strongly curved trench, or a region that covers more than one zone) needs a --clip, a different --columns or --cell-size, or an external mesh; the recipes say which.
