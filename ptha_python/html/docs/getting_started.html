Start

Start here: from zero to your first result

This page takes you from an empty computer to an open report, one small step at a time. Click a step to open it. Every step says what you type, and what that does. You do not need to know Python to follow it. You only need to copy the commands into a terminal.

The whole path in one picture

The steps

Every command is typed in a terminal, from the repository root: the folder that holds ptha_python/, rptha/ and inputs_meshes/. It is the folder that git clone creates.

Step 1. Install what you need once

What this does: makes sure your computer has the three things the code needs. You only do it once.

  • Python 3.11 or newer. The code was tested on 3.11 and 3.13; older versions were not tested. Check it with python --version (on macOS and Linux, python3 --version).
  • git, to download the code. Check it with git --version.
  • An internet connection for the first run of a zone (about 30 MB of earthquake catalogue is downloaded once).
  • R is not needed. Only the optional comparison with PTHA18 (the last box below) uses it.
Step 2. Get the code once

What this does: copies the repository to your computer and moves the terminal into it.

git clone <repository URL>
cd <the cloned folder>

Replace the two placeholders with the address of the repository and the name of the folder that git clone creates. From now on, every command is typed in this folder.

Step 3. Create the environment once

What this does: creates a private Python installation inside the folder (.venv) and installs the packages the code uses (numpy, scipy, pandas, matplotlib, shapely, geopandas, pyproj, netCDF4 and pillow). Nothing is installed in the rest of your computer. Pick your system:

py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
If PowerShell refuses to run the activation script, type Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, and activate again.
py -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

When the environment is active, the prompt starts with (.venv). Activate it again every time you open a new terminal (the second line above). Check that everything works:

python ptha_python/generate.py --help

It prints every option. A ModuleNotFoundError means the environment is not active, or the pip install did not finish.

Step 4. Choose your zone 2 minutes

What this does: lists the regions the code can build. Each region comes from a public model of the plate interface (SLAB2.0 or SLAB1.0, from the USGS).

python ptha_python/list_regions.py

You will need two names in the next step:

  • The region (for example kermadec or calabria): which part of the world to build. It is the first word of the generate command.
  • The zone (for example kermadectonga2, passed with --zone): which source zone inside the region. Some regions hold several zones, so give it whenever you are not sure.

The zones you can run, and the region that goes with each, are listed in Zones you can run. A ready-made command for each zone is in Recipes.

Step 5. Generate the folder 1 second

What this does: writes a new folder with a copy of the nine step scripts, already filled in for your zone, plus a README.md and a RUN.html that record exactly what you asked for. It reads only local files, downloads nothing and takes a second or two.

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2

The options you give here decide what comes out. The rest of the run only follows them. For a first run, the command above is enough. When you want something different, these are the choices that matter most:

OptionWhat it changes in the result
--zoneThe source zone. It sets the literature values the run uses (largest magnitude, coupling, b value).
--rupture-size rptha|localHow big each rupture is. rptha is PTHA18's rule (one block of cells per magnitude). local sizes each rupture from the real area of the cells where it sits, which suits meshes whose cells vary a lot in size.
--columns and --cell-sizeHow the mesh is cut: how many unit sources along strike, and how large they are. This changes every number downstream.
--clipKeeps only a window of the SLAB model, for a region that covers more than your zone.
--mesh-fileUses your own mesh instead of building one from SLAB (see Your own mesh).
--ptha true|falseWhether the steps may read PTHA18's own cell sizes (only for zones PTHA18 modelled). false uses public data only.
The complete list is in the guideEvery option, its default and the combinations the program refuses are in Options, files, columns: generate.py options. Read that table before you change anything: it is the key to what you will get. If you prefer to build the command by clicking, use the command builder at the end of the Quick start.

If the folder name is already taken, generate.py never overwrites it: the new folder is called NAME_2, then NAME_3, and so on.

Step 6. Run it 2 to 5 minutes

What this does: runs the nine steps one after the other. The first run of a zone downloads about 30 MB of earthquake catalogue, and later runs reuse it.

python kermadectonga2/steps/step_total.py --skip-official

Use the folder name you chose in step 5. --skip-official leaves out the optional comparison with PTHA18, which needs R. The screen names each step as it starts (>>> step1_fetch_slab2.py) and ends with Done in 3.3 min. See kermadectonga2/report.html. If a required step fails, the run stops there and prints why.

What each step does, in plain words:

Run stepNameWhat it does
1Contours from SLABReads the depth model of the plate interface and draws lines of equal depth, every 5 km below the trench. This is the shape of the fault.
2The meshCuts that surface into a grid of small rectangles, the unit sources. Everything later is computed per unit source.
3Plate convergenceLooks up how fast the two plates approach each other along the trench (Bird, 2003). It also writes the mesh/ folder with a 3D page of the mesh.
4GCMT catalogueDownloads the Global CMT catalogue of past earthquakes (the only large download).
5Earthquakes of the zoneKeeps the earthquakes that happened on this interface, to fit how often large ones occur.
6The input fileCollects every number the engine needs into one file, inputs/input_<zone>_scratch.json, and notes where each number comes from.
7Logic tree and ratesThe engine. It builds the possible ruptures and computes how often each magnitude is exceeded, over many alternative models (the logic tree).
7b, 7cSlip variants optional7b builds ruptures with uneven slip. 7c uses a shear modulus that changes with depth (only with --variable-mu on).
8PTHA18's own run optionalRuns the official PTHA18 inputs through the same engine, for a comparison. Needs R.
9The reportWrites report.html, one page with every figure and number above.

More detail on each step is in The nine steps.

Step 7. Open the results the reward

What this does: nothing to type. Open these files by double-clicking them. They are inside the folder you generated.

FileWhat it is
report.htmlStart here. The whole run on one page: every step, the numbers, the mesh on a map and the exceedance-rate curve. Reading report.html explains it.
mesh/mesh_3d.htmlThe mesh in 3D and in plan, with the SLAB contours it was cut from and the length x width of every cell. Use it to check that the mesh follows the fault. Needs an internet connection to draw (it loads Plotly).
outputs/rate_curves.csvThe main result: how many earthquakes per year exceed each magnitude.
outputs/exceedance_rate_percentiles.csvThe same curve with its uncertainty (percentiles over the logic tree).
outputs/scenario_rates_<zone>.csvThe rate of every individual rupture scenario.
mesh/mesh_cell_corners.csv, mesh/mesh.datThe mesh as plain text: the four corners of every cell (mesh.dat can be fed back to generate.py with --mesh-file).
RUN.htmlThe exact commands that created the folder. Keep it: it is the record of how to reproduce the run.
Step 8. Change a setting and run again when you want

What this does: lets you try a different setting without generating a new folder.

Two ways, depending on the setting:

  • An option of generate.py (step 5): generate a new folder with the new option. The old one stays untouched, so you can compare the two.
  • A constant at the top of a step script: open the script in a text editor, change the value, and run that step and the ones after it again. For example, for cells of 40 km instead of 50 km, edit DESIRED_LENGTH_KM and DESIRED_WIDTH_KM in steps/step2_build_grid.py, then run the scripts step2, step3, step5, step6 (with --force), step7, step7b and step9 again, in that order.

The table of which settings live where, and which steps to repeat, is in Change a setting, re-run.

Extra: compare with PTHA18 optional, needs R

What this does: for a zone that PTHA18 modelled, it also runs the official PTHA18 inputs and puts the two results side by side in the report.

It needs R with the rptha package and a one-time download of 1.34 GB. Leave out --skip-official in the run command (step 6 of this page) to try it. If R is missing, that step stops with a message, the rest of the run finishes and the report simply has no comparison. See The official PTHA18 run.

If something goes wrong

What you seeWhat to do
ModuleNotFoundErrorThe environment is not active. Repeat the activation line of step 3 in this terminal.
PowerShell says running scripts is disabledType Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, then activate again.
matches more than one zoneAdd --zone to the generate command (step 4 and step 5).
Step 1 stops with HTTP 403The USGS server refused a scripted download. The message names the file and the folder: download it in a browser and put it there, then run the step again.
A step stops with an errorRead the last lines it printed. Troubleshooting lists every message and its fix.

The short version

After the installation, a new zone is only the two commands under "for every zone". This is the Windows PowerShell version; on macOS and Linux, use the activation line of step 3.

# once
git clone <repository URL>
cd <the cloned folder>
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# for every zone
python ptha_python/generate.py calabria --zone calabria2 --rupture-size local
python calabria2/steps/step_total.py --skip-official
# then open calabria2/report.html and calabria2/mesh/mesh_3d.html
