Your own runs

Change a setting, re-run

Every zone folder can be changed. Each setting lives in one place: a constant at the top of a step script, a key of the input JSON, or an option of generate.py. Change it there, then re-run the step and every step after it. This page lists where each setting lives, gives a recipe for the changes people ask for most, and shows two worked changes.

At a glance: what to re-run

Step 7 replaces the whole outputs/ folder, including the results of steps 7b and 7c. After re-running step 7, run 7b and 7c again (if the folder uses them) before step 9, or the report has no HS and VAUS section.

Where each setting lives

Hand edits are kept, until you rebuildStep 6 writes the input JSON once. If the file already exists, step 6 prints already exists, NOT overwriting it and keeps it, so your edits stay. step6_write_input.py --force rebuilds the file and discards them. So does step_total.py --auto-clip. The same rule hides upstream changes: if you change step 2 or 3 and run step_total.py without --force on step 6, the old JSON is used.

In a step script

Each step script has its settings as constants at the top of the file, after the paths. Edit the constant, save, and run that script and the steps after it. Every constant of every step is listed in Options, files, columns. The ones that matter for a change:

In the input JSON

Step 6 writes inputs/input_<zone>_scratch.json, which step 7 runs. Edit it to change the logic tree or the observed events. The keys that are often changed (the block is the key one level up):

KeyWhat it does
rates.tectonic_convergence_mm_per_yrthe convergence of the zone as one number, in mm/yr. With Bird's values, the per-column profiles sit beside it as rates.convergence_profile and rates.convergent_slip_profile
rates.couplingthe coupling prior: spreadsheet_values as [min, preferred, max], uniform_range ([0.1, 1.3]) and prob_zero_coupling
rates.b_anchorthe range of the b value of the logic tree, as [min, preferred, max]
rates.Mw_max_anchor, rates.mw_max_observedthe range of the maximum magnitude ("derive", or a pair), and the largest observed earthquake it is derived from
rates.Mw_min, rates.Mw_frequency_distribution_prob, rates.n_logic_tree_binsthe minimum magnitude ([7.15]), the 70/30 weights of the two Gutenberg-Richter types, and the number of values of each axis (coupling 20, b 20, Mw_max 40)
events.Mmin, events.Mmax, events.dMwthe magnitudes of the scenario ruptures: 7.2 to 9.8 in steps of 0.1
events.scaling_relation, events.shear_modulus_Pathe rupture scaling relation and the rigidity (30 GPa for the constant model)
geometry.desired_unit_source_width, geometry.desired_unit_source_lengththe unit-source size the rupture sizes are built from. A change makes the engine mesh again instead of reusing step 2's grid
rates.update_logic_tree_weights_with_data, rates.observed_seismicitywhether the observed GCMT events move the weights (LEVEL 3), and the events with their threshold, count and duration
rates.edge_correctionthe LEVEL 4 edge correction: fit, fixed, inherit or off
percentilesLEVEL 5: threshold_Mw (the magnitudes), N (40,000 samples), percentile_probs and seed (123)
segmentsthe LEVEL 0 segments of a segmented run; empty for an unsegmented run

The keys that begin with an underscore (such as _convergence_provenance) are notes that record where each value came from. The full layout is on The input file.

In generate.py

The options (listed in Options, files, columns) are written into the folder when it is made. They cannot be changed in place. To try another option, run generate.py with a new --folder. If the folder name is taken, generate.py adds a suffix such as _2, so no folder is overwritten.

The 7b and 7c steps are listed after step 7 because step 7 deletes their results. If you only change something in step 7b, steps 7 and the earlier ones keep their results.

Running again in the same folder

  • The input JSON is kept. step_total.py does not pass --force to step 6 (only --auto-clip does), so a changed constant in step 2 or 3 does not reach the JSON until step 6 is run with --force.
  • Step 7 replaces outputs/ as a whole, so the HS, VAUS and variable shear modulus results are gone until 7b and 7c run again. step_total.py runs them.
  • Downloads are kept. Step 4 reuses the .ndk files in data/gcmt/ (delete a file to download it again), and step 1 reuses the SLAB raster, from the folder or from ptha_python/data/slab2/.
  • Step 8's results stay in outputs_official/ until step 8 runs again.
  • The report and RUN.html. Step 9 writes report.html again. Each complete step_total.py run adds a line to RUN.html.
  • To keep the old results, copy the folder first, or generate a new one: nothing in a folder depends on another.

Example 1: a constant convergence

Suppose you want every column to use one convergence rate, for example to reproduce the constant 35 mm/yr PTHA18 used on puysegur2. Step 3 has a constant for it.

  1. In NAME/steps/step3_convergence.py, set CONVERGENCE_OVERRIDE_MM_PER_YR = 35.0, in mm/yr.
  2. Run python NAME/steps/step3_convergence.py. It prints that the override replaces the Bird value.
  3. Run python NAME/steps/step6_write_input.py --force. The JSON now holds the constant. Step 6 says that the run uses the constant-convergence model.
  4. Run python NAME/steps/step7_run.py, then step7b_stochastic_slip.py and step7c_variable_mu.py if the folder uses them, then python NAME/steps/step9_report.py.
Always the horizontal rateThe number is the horizontal plate rate. The engine divides it by the cosine of the mean dip itself. Typing a value already divided by the cosine applies the correction twice.
Compare like with likeA rate from a constant convergence is not comparable with a rate from the Bird values. Keep the same value in both runs when you compare them.

Example 2: a different b value, from the JSON

The logic tree's b values are in the input JSON, so no step has to be re-run before step 7.

  1. Open NAME/inputs/input_<zone>_scratch.json and change rates.b_anchor, keeping the form [min, preferred, max].
  2. Run python NAME/steps/step7_run.py, then step7b and step7c if the folder uses them, then python NAME/steps/step9_report.py.

Step 6 is not run again, so your edit survives. Running step_total.py also keeps it, because step 6 does not overwrite the file.

Check that a change took effect

  • Steps 2 and 3: the printed mesh and convergence lines show the new value. The files are data/slab2/unit_source_grid.npy and data/convergence.txt.
  • Step 6: the input JSON has the new value, and its _provenance notes say where it came from.
  • Step 7: the summary in outputs/logic_tree_summary.csv and the rates in outputs/rate_curves.csv change.
  • Step 9: the report's header and the "Step by step" cards show the new numbers. A stale report is one that was not re-run after the change.
