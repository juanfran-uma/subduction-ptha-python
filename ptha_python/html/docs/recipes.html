Your own runs

Recipes: one per zone

For each zone that has a worked recipe: the command that generates its folder, the command that runs it, and the settings that matter for that zone. The commands are run from the repository root. Every command on this page is accepted by generate.py.

These pages describe proceduresNo finished run ships with the repository. The folders below do not exist until you generate them, and a folder that already exists is not replaced: generate.py makes NAME_2 instead. The GCMT catalogue is downloaded into each folder, so the first run of a folder takes longer than a re-run in the same folder. A SLAB2.0 raster is downloaded into the folder too, unless a copy is already in ptha_python/data/slab2/, which holds the rasters of cal, car, hel, ker, mak, png, puy and sum.

At a glance

Every recipe has the same two steps. The generate command makes the folder, and the run command runs all nine steps. Step 8 is skipped with --skip-official because it needs R with rptha. Remove that flag when R is installed, to get the comparison with PTHA18's own run (for the zones PTHA18 modelled and has not retired).

The settings the recipes share

  • --ptha false is the default and is written out so the recipe says it. Steps 1 to 7 and 9 read no PTHA18 file.
  • --rupture-size local sizes each uniform-slip rupture from the real area of the cells where it sits, and multiplies its probability by q, the rupture-overlap correction. The recipes use it because these zones have cells of very different sizes, which the rptha rule (one block of cells per magnitude) does not follow. It is not PTHA18's procedure. Leave it out to get rptha's rule. See Rupture size.
  • --skip-official skips step 8, which needs R with rptha. Steps 1 to 7 and 9 need nothing but Python.
  • Step 7b is kept, so the run includes the illustrative HS and VAUS variants (HS and VAUS slip).

alaskaaleutians, from a mesh file

The Alaska-Aleutians zone from an external quadrilateral mesh: one line per unit source with its four corners. The file is copied into the folder, and the SLAB geometry is not used (External mesh).

python ptha_python/generate.py alaska --zone alaskaaleutians --mesh-file inputs_meshes/alaskaaleutians_quadrilateral_coors.dat --folder alaskaaleutians_mesh --ptha false --rupture-size local
python alaskaaleutians_mesh/steps/step_total.py --skip-official

Step 1 only notes that the geometry comes from the mesh, and step 2 reads it: this mesh has 78 columns and 4 rows, 312 unit sources, with depths given in metres (read as such by --mesh-depth-units auto). The mesh must be structured (rows down dip, columns along strike, neighbouring cells sharing their corners). Options that only shape a SLAB mesh, such as --clip, --columns and --cell-size, are refused or have no effect here.

alaskaaleutians, from SLAB

The same zone built from the SLAB1.0 raster, to compare with the mesh file above.

python ptha_python/generate.py alaska --zone alaskaaleutians --folder alaskaaleutians_slab --ptha false --rupture-size local
python alaskaaleutians_slab/steps/step_total.py --skip-official

The region name alaska is the SLAB region, and --zone alaskaaleutians is the zone. SLAB1.0 is chosen because the zone name does not end in 2. Each folder has its own report, so the two can be compared.

calabria2

The Calabrian arc in the Ionian Sea, a strongly curved trench. Step 1 cuts both ends automatically at the end points of Berryman et al. (2015) Table 3.1. No option is needed for that.

python ptha_python/generate.py calabria --zone calabria2 --folder calabria2 --ptha false --rupture-size local
python calabria2/steps/step_total.py --skip-official

Check the mesh. Step 2 prints how the cells taper along the zone. This zone tapers far more than any PTHA18 mesh, and with the default --columns trench some cells are much larger than the 50 km of a typical cell. If the cells look unsuitable on the step 2 figure, two alternatives are available, both not PTHA18's procedure: --columns average (or average-edited) uses the average row length to set the number of columns, and --cell-size strasser caps every cell so that none is larger than the smallest rupture the run builds, divided by --cell-k. The reasons and the trade-offs are on optimal, lm and mid and Cell size.

python ptha_python/generate.py calabria --zone calabria2 --folder calabria2_avg --ptha false --rupture-size local --columns average-edited
python calabria2_avg/steps/step_total.py --skip-official

python ptha_python/generate.py calabria --zone calabria2 --folder calabria2_strasser --ptha false --rupture-size local --cell-size strasser
python calabria2_strasser/steps/step_total.py --skip-official

A run with --columns average-edited printed, in step 2, taper 3.83 (at most 1.17), column rule 'average': average row 393 km / 50 km -> 8 columns (rptha's trench rule: 15), a mesh of 8 columns by 6 rows (48 unit sources, 109,203 km2), and that no cell's dip was more than 8 degrees from its plane (worst 3.3 degrees), so the mesh was kept. Step 5 found no GCMT event above Mw 7.15 on the zone, and step 7 derived an Mw_max anchor of 7.35 to 9.26 for this mesh. The variants are separate folders, so the default run is kept for comparison.

antilles2

The Lesser Antilles arc alone. The SLAB2.0 "Caribbean" region covers more than this zone, and the zone has no built-in window, so the raster must be clipped with --clip.

python ptha_python/generate.py caribbean --zone antilles2 --folder antilles2 --ptha false --rupture-size local --clip 297,307,5,18.5
python antilles2/steps/step_total.py --skip-official

The clip is LON_MIN, LON_MAX, LAT_MIN, LAT_MAX. Longitudes follow the raster's own convention, which runs from 0 to 360 for this region, so 297 to 307 is 63 degrees west to 53 degrees west. Without --clip, step 1 works on the whole region, which covers more than this zone. --clip must have the minimum below the maximum for both longitude and latitude, and a value that starts with a minus sign needs --clip=....

A clip can still cut another slabA window that also contains a neighbouring slab is not detected by the program. Check the step 1 figure for a strip of another plate's trench at the edges of the window.

cyprus2

The Cyprus arc, which the Berryman et al. (2015) table splits into a western and an eastern segment. Its SLAB region is the Hellenic Arc, hellenic: the region name cyprus matches no region. As with calabria2, step 1 cuts both ends at the Berryman end points automatically.

The arc bends in an S shape, so the rows of some cells can run along strike rather than down dip. The recipe therefore uses --columns trench-edited. It keeps the trench mesh unchanged unless some cell reads a dip more than 8 degrees away from the dip of its own plane; only then does step 2 design a replacement, with the same columns and rows on the same contours, and use it if it is safe:

python ptha_python/generate.py hellenic --zone cyprus2 --folder cyprus2 --ptha false --rupture-size local --columns trench-edited
python cyprus2/steps/step_total.py --skip-official

The -edited options are not PTHA18's procedure. If the mesh is replaced, its rates are not comparable with those of the plain trench mesh. Without the option, the same command with the default --columns trench gives the plain mesh; give it another folder name so both runs are kept. Their rules are on optimal, lm and mid.

kermadectonga2

The Kermadec and Tonga trench. Step 1 cuts its ends where the SLAB2.0 data is not usable, without any option (Clean ends).

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2 --ptha false --rupture-size local
python kermadectonga2/steps/step_total.py --skip-official

The region kermadec also holds the SLAB1.0 zone kermadectonga, which PTHA18 retired. Use --zone to say which one is wanted, as above. To run the zone with its segments, add --segmented true (Segmented vs unsegmented):

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_seg --segmented true --ptha false
python kermadectonga2_seg/steps/step_total.py --skip-official

A run of this command (with the default rupture size) split the mesh of 73 columns and 3 rows (219 unit sources) into three segments by the Berryman end points: tonga (columns 1 to 23, 3 GCMT events), kermadec (24 to 57, 6 events) and hikurangi (58 to 73, no event), and wrote report_unsegmented.html next to report.html.

kurilsjapan, with a cut tail

The Kamchatka, Kuril Islands and Japan region can reach past its own plate boundary, onto a neighbouring trench. Step 3 checks whether the columns of the mesh lie on a different plate boundary and reports it. --auto-clip cuts those columns, using a window derived from the mesh itself, so no coordinates are typed.

The check is made from the mesh, so steps 1 to 3 must have run once. Generate the folder and run those three steps first:

python ptha_python/generate.py kuril --zone kurilsjapan --folder kurilsjapan --ptha false --rupture-size local
python kurilsjapan/steps/step1_fetch_slab2.py
python kurilsjapan/steps/step2_build_grid.py
python kurilsjapan/steps/step3_convergence.py

Step 3 saves data/plate_boundary_change.json only if it finds such a tail. Then run the whole pipeline with the cut. It runs all nine steps again on the clipped geometry:

python kurilsjapan/steps/step_total.py --skip-official --auto-clip

Because the cut rebuilds the mesh with fewer columns, step 6 is run with --force, which regenerates the input file. A hand edit made to that file is lost, so re-apply it afterwards. If a longitude and latitude box cannot separate the tail from the rest of the arc, step 1 refuses and asks for an explicit --clip (Troubleshooting).

makran2

The Makran zone along the coasts of Iran and Pakistan.

python ptha_python/generate.py makran --zone makran2 --folder makran2 --ptha false --rupture-size local
python makran2/steps/step_total.py --skip-official

The trailing 2 in the zone name selects SLAB2.0. The zone makran (SLAB1.0) is retired in PTHA18 and has no SLAB1.0 grid on the USGS server, so makran2 is the zone to use.

puysegur2

The Puysegur trench south-west of New Zealand's South Island. Step 1 decides the ends of the zone, as for every zone.

python ptha_python/generate.py puysegur --zone puysegur2 --folder puysegur2 --ptha false --rupture-size local
python puysegur2/steps/step_total.py --skip-official

To add PTHA18's variable shear modulus rates next to the constant ones, generate with --variable-mu on (the run then also executes step 7c, Variable shear modulus). A run with --rupture-size local --variable-mu on gave a mesh of 13 columns and 2 rows (26 unit sources, 43,468 km2), a Bird convergence of 25.6 mm/yr, and 4 GCMT events above Mw 7.15.

The convergence. PTHA18 used a constant 35 mm/yr for this zone, not the value Bird (2003) gives on its mesh (generate.py prints a note about it). This package uses Bird's value by default. To reproduce PTHA18's choice, set CONVERGENCE_OVERRIDE_MM_PER_YR = 35 in steps/step3_convergence.py, then run steps 3, 6 (with --force), 7 and 9 again. Step 7 replaces the whole outputs/ folder, so run step 7b (and step 7c, if the folder uses it) after it and before step 9 if you want the HS and VAUS results in the report. The reasons for the two values are on Bird or Bird + Griffin.

python puysegur2/steps/step3_convergence.py
python puysegur2/steps/step6_write_input.py --force
python puysegur2/steps/step7_run.py
python puysegur2/steps/step7b_stochastic_slip.py
python puysegur2/steps/step9_report.py

With --variable-mu on, add python puysegur2/steps/step7c_variable_mu.py after step 7b.

Other zones

A zone without a recipe is generated the same way. Find its region in Zones you can run (or with python ptha_python/list_regions.py, or use --id), pass the zone with --zone, and read the page on the zone's own mesh: The mesh for the general behaviour, Clean ends for the end cuts, and Troubleshooting when a step stops. To change a setting of a run you have made, see Change a setting, re-run.
