8. The official PTHA18 run

Step 8 answers one question: what would this same engine give with PTHA18's own inputs? It takes PTHA18's published mesh, its parameters, its convergence and its observed earthquakes, and runs them through exactly the engine step 7 uses. The difference between the two runs is then only the inputs, never the code. It is optional, and it needs R.

At a glance

NeedsR with the rptha package (Rscript on the PATH, or in C:\Program Files\R\); curl; a zone that PTHA18 modelled; an internet connection the first time. Steps 1 to 7 are not required (step 8 reads none of their files, except to see whether the run is segmented), but step 9 compares the two runs. Details.
Writesthe shared inputs/input_<zone>.json of the repository, the folder's copy inputs/input_<zone>_official.json, outputs_official/ and outputs_official/ptha18_reference/; a segmented folder also runs/python/<zone>_official_segmented/ and ptha18_reference/official_segments.json.

Why it needs R

PTHA18's logic-tree weights after its Bayesian update, and its parameter table per zone, live inside the R objects of its saved session: values that only exist once R loads them. No Python reader can get at them directly. So step 8 calls R once, through official_ptha_data/fetch_official_inputs.py and its R script extract_official_tree.R, to extract the official tree, and from then on everything is Python. Step 8 checks that Rscript is installed before it starts.

Zones PTHA18 never modelledcalabria2, caribbean2 and antilles2 have no official run: they are not in PTHA18's sourcezone_parameters.csv. Step 8 then writes outputs_official_status.txt (first line not_a_ptha18_zone), prints that there is no official run to compare with, and ends normally. Step 9 reads that file and leaves out the comparison sections, saying why. Steps 1 to 7 and 9 are complete without it.
Retired zonesPTHA18 retires a zone by giving it row_weight = 0 in its table (kermadectonga, puysegur, newhebrides, sunda, solomon, makran, timor, flores, newguinea, macquarienorth, and others). Their rows exist, but the saved session holds no logic tree for them. fetch_official_inputs.py stops at once with "is a retired source zone" and names the successor, for example kermadectonga2, so step 8 fails (exit code 1) before the long download of the session. Use the zone with the "2" name.

What you need installed, and what happens without R

  • R, found in this order: Rscript on the PATH, then the newest R-* folder under C:\Program Files\R\ (Windows). On Linux or macOS Rscript must be on the PATH.
  • The rptha R package and its dependencies. This repository's rptha/ folder holds only a few data files (sourcezone_parameters.csv and other tables), not the R package. Clone GeoscienceAustralia/ptha somewhere (on Windows also install Rtools, because rptha has Fortran code) and from that clone run: 
    Rscript -e "install.packages(c('geosphere','sp','sf','raster','FNN','minpack.lm','geometry','ncdf4'), repos='https://cloud.r-project.org')"
Rscript -e "install.packages('R/rptha', repos=NULL, type='source')"
  • curl on the PATH, which downloads the session and the zone's files. Step 8 stops with "curl not found" otherwise.
  • The Python packages of requirements.txt (netCDF4 for PTHA18's cell table; geopandas for PTHA18's published cell outlines, optional: if that fails the report just omits that layer).
  • About 1.4 GB of disk for the saved session, and minutes of time and memory the first time R loads it. Reruns reuse the downloaded session and the extracted trees.

Without R, step 8 prints "Rscript not found" with the install instructions above and exits with an error, before downloading anything. Nothing else breaks: step_total.py says that step 8 is optional and continues to step 9 (or you skip it with --skip-official), and the report is complete for this run, without any comparison section. R is needed on every run of step 8, even when the trees were already extracted.

What it does, in order

  1. Download (once) PTHA18's saved session (1.34 GB) and the zone's cell table unit_source_statistics_<zone>.nc from NCI's public server.
  2. Extract with R the official logic tree and each zone's parameters.
  3. Read the zone's row of PTHA18's sourcezone_parameters.csv: coupling, b-value, largest observed magnitude, and whether it uses Bird's convergence.
  4. Recover the convergence from the session. PTHA18 stores the slip on the fault, and the script inverts it back to the horizontal rate.
  5. Read PTHA18's observed earthquakes (the LEVEL 3 data: magnitude threshold, event count, window in years and each magnitude) out of the same session, so the Bayesian update reproduces PTHA18's.
  6. Write inputs/input_<zone>.json, with a _provenance note on each field, and geometry mode official_statistics (the engine reads PTHA18's cell table directly, with no meshing).
  7. Check it against the session: the geometry area, the mean dip, the convergence, a control inversion (the same inversion returns 35 mm/yr on puysegur2, when that zone is among the extracted ones), and the Mw_max axis. Each check prints PASS or FAIL; any FAIL ends the run with "VERIFICATION FAILED" and exit code 1.
  8. Add PTHA18's Bird model when the zone uses Bird: the per-column profiles computed on PTHA18's own mesh with lib/bird_convergence.py and the Bird+Griffin table, checked against the official convergence (step 3).
  9. Add PTHA18's segments, only when the folder is segmented: every segment row of sourcezone_parameters.csv for the zone (its columns of PTHA18's mesh, coupling, b range, mw_max_observed) with the GCMT events the saved session gives that segment. The run is then PTHA18's own segmented model, written to runs/python/<zone>_official_segmented/. The validation script checks this against PTHA18's segment trees and scenario rates (validate_against_ptha18.py official_segments and events_segmented).
  10. Set the percentile magnitudes of the official input to every 0.1 from 7.2 to 9.8, the same as step 6's, so the report compares the two runs at every one of them (only LEVEL 5's output rows change, no rate does).
  11. Run the engine on the folder's copy of that file, and copy its output to outputs_official/ (an existing outputs_official/ is replaced).
  12. Write the PTHA18 reference for the report into outputs_official/ptha18_reference/ (below).

Where in the code: steps/step8_official.py (check_rscript(), add_bird_model(), add_official_segments(), write_reference(), main()), official_ptha_data/fetch_official_inputs.py, lib/bird_convergence.py (column_convergence(), ptha18_uses_bird_convergence()).

The only step that reads PTHA18

With --ptha false, steps 1 to 7, 7b and 9 open no file of PTHA18 or of rptha (what each step reads; the check is described in Data provenance). Everything of PTHA18 that the report compares with is therefore collected here, by step 8, in outputs_official/ptha18_reference/. The report reads PTHA18 from nowhere else:

Options and the outputs_official/ layout

Step 8 has one command-line option:

optionmeaning
--download-hsdownload PTHA18's published HS and VAUS catalogues for the zone (all_stochastic_slip_earthquake_events_<zone>.nc and all_variable_uniform_slip_earthquake_events_<zone>.nc, from NCI, hundreds of MB each) into official_ptha_data/public_nc/, and compare step 7b's fields with them. It does something only if step 7b has already run (otherwise there is nothing to compare, and step 8 says "step 7b has not run"). A file that PTHA18 never published for the zone (HTTP 404) is skipped with a message. Off by default, because it is a large download. step_total.py --download-official-hs-vaus passes it on; step_total.py --skip-official skips step 8.

Step 8 does not read --ptha or any other generate.py option except the zone and whether the run is segmented (from step 6's input JSON, if it exists). Its other settings are not options: the catalogue magnitude tolerance for the HS/VAUS comparison is 0.05 (OFFICIAL_MW_TOL), and the percentile magnitudes are every 0.1 from 7.2 to 9.8.

The session is looked for first in official_ptha_data/session/, then in the repository root, then in the folder above it, and downloaded to the first place if none has it. A file smaller than 1 GB is rejected as truncated. A .part file left by an interrupted download is never used.

What the report compares

When outputs_official/ exists, step 9 adds PTHA18's side to these parts of the report (the report guide):

  • Table of this run against PTHA18: mean dip, convergence, edge multiplier, prior to posterior shift (total variation distance) and the exceedance rate at Mw 7.2, each with the percentage difference. On a segmented run, also each segment's convergence.
  • The exceedance-rate curve: PTHA18's logic-tree mean curve, dashed, next to this run's band.
  • Mesh: PTHA18's cell table drawn beside this run's mesh (plus its published outlines on the web map), and the convergence on both meshes, with the convergence profile per along-strike column of each.
  • Observed earthquakes: PTHA18's LEVEL 3 count and window next to this run's step 5 count.
  • Branch weights and the prior fan of PTHA18's run, and its integrated slip.
  • HS and VAUS: per magnitude, step 7b's fields against PTHA18's catalogue (event counts, mean peak slip, active cells, concentration, spectral distance), only when the catalogues are present.
  • CSV exports in outputs/exports/: the files with the suffix _official (for example posterior_mean_rate_curve_official.csv, mesh_cells_official.csv, convergence_official.csv, convergence_profile_official.csv), next to this run's.

Why the official run is trustworthyWith PTHA18's own inputs, this engine is checked against PTHA18's published results: the validation script compares the branch weights, the scenario rates and the percentiles with PTHA18's own. See Validation.

Run it

python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2
python kermadectonga2/steps/step8_official.py
python kermadectonga2/steps/step8_official.py --download-hs   # also PTHA18's HS/VAUS catalogues, for step 7b's comparison
python kermadectonga2/steps/step9_report.py   # to see the comparison

# a SEGMENTED folder: the same commands on its own folder; step 8 then runs PTHA18's segmented model
python ptha_python/generate.py kermadec --zone kermadectonga2 --folder kermadectonga2_seg --segmented true
python kermadectonga2_seg/steps/step8_official.py
python kermadectonga2_seg/steps/step9_report.py

The first run on a machine downloads the session and loads it into R, which takes minutes; later runs reuse the downloaded session and the extracted trees (R is still started). step_total.py --skip-official skips step 8 entirely. Run it from the repository root, like every other step.
