Geometry: from SLAB to mesh

Cell size: --cell-size strasser

By default the unit sources are sized on average, about 50 x 50 km. On a fan-shaped zone, or one whose width changes along strike, some cells then come out far larger than the earthquakes the run builds. --cell-size strasser caps the size of every cell instead, so that no cell is larger than a rupture of the smallest magnitude the run uses, divided by --cell-k.

At a glance

Writesthe same data/slab2/unit_source_grid.npy as the default, with cell_size, cell_k and the cap in its fingerprint, so a changed setting rebuilds the mesh.

Why a cap is needed

The default rule sizes the cells on average. Its columns come from the trench length divided by 50 km, and its rows from the mean down-dip length divided by 50 km. On a fan, where the deep contours are much shorter than the trench, the cells at the trench become much longer than the cells at depth. On calabria2, the trench is 717 km long after the Berryman end cut, and the rows are 6 deep. Its largest cell is 2612 km² and its widest cell is 61.5 km. A Strasser rupture at Mw 7.2 is about 54 x 44 km, or about 2400 km², so one cell can be bigger than the whole rupture.

This matters for two reasons. A rupture cannot be smaller than one cell, so ruptures built with --rupture-size local cannot take the size of the scaling relation where the cells are too large. The same holds for the variable-slip footprints of step 7b. Capping the cells makes both fit.

The rule

  1. The cap. Strasser's scaling relation gives the rupture size at the smallest magnitude the run builds (Mw 7.2 in the default run). That length and width are divided by --cell-k. With the default k = 1.5 the cap is 36.2 x 29.5 km. With k = 2 it is 27.2 x 22.1 km (strasser_cell_cap()). Step 2 prints it: --cell-size=strasser: no unit source longer than 36.2 km or wider than 29.5 km (Strasser at Mw 7.2 / 1.5); rows and columns raised until every cell meets the cap.
  2. The first mesh. The same optimal mesher as the default builds the mesh, with the cap values as its cell-size targets in place of the default 50 km.
  3. Check. The longest and the widest cell are measured. If the widest cell is wider than the cap, rows are added. If the longest cell is longer than the cap, columns are added. Both use a 2% tolerance.
  4. Repeat. The mesh is rebuilt with the new counts and checked again, up to 40 meshes. Every try is printed as cell cap: C x R cells, longest L km (cap ...), widest W km (cap ...), so you can follow the process in step 2's log (the calabria2 run with k = 1.5 prints 20 x 11, 20 x 13, 21 x 13 and 22 x 13). If the cap is not met after 40 meshes, step 2 stops with an error.

The minimum of two down-dip rows still applies. The cells are not made equal, and the number of rows and columns is not fixed by any target.

Where in the code: pyptha/contour_discretisation.py strasser_cell_cap() and discretized_source_from_contours_bounded(); templates/step2_build_grid.py.tmpl (CELL_SIZE, CELL_K, CELL_CAP_MW, CELL_CAP_RELATION). Step 6 reads those four constants from the step 2 script and writes them as cell_size, cell_k, cell_cap_mw and cell_cap_relation into the geometry block of the input JSON (and n_downdip as null), so the engine, step 7b and step 9 build the same mesh.

CELL_CAP_MW = 7.2 and CELL_CAP_RELATION = "Strasser" are constants in step 2, not options. They must equal the smallest magnitude and the scaling relation of the event table, which step 6 writes into the events block of the input JSON (Mmin, 7.2 in the script; scaling_relation). If you change one of those, change the cap constants too and redo the steps that depend on the mesh in order: step 2, step 3, step 5, step 6 with --force (which discards other hand edits of the JSON), then step 7 onward.

The longest cell of the capped mesh is 36.9 km against a cap of 36.2 km, inside the 2% tolerance. The total area of the mesh does not change much, because both meshes cover the same surface. The cap changes how the surface is divided, and therefore which scenarios are possible. The rates can change with it, and this page does not give a rate comparison. The effect on the tsunami hazard has not been measured in this repository.

Measured with the current code on the default calabria2 contours (step 1 with its Berryman end cut, --ptha false). To reproduce a row, run the commands below. Step 2 prints the grid line and the ranges of cell length and width. The areas in the table are the length times the width of the largest cell.

Costs and limits

  • More unit sources. The capped calabria2 mesh has 286 unit sources against 90 for the default, about three times as many. Every later step works on each unit source, so expect longer runs.
  • Needs --discretizer optimal. Any other choice stops at generate time with a message.
  • Cannot be combined with --mesh-file. A mesh file is used as given, so there is nothing to cap.
  • Columns and targets are not used. The column count and the rows come from the cap, so the 50 km targets, --ptha true's per-zone width and official row count, and N_DOWNDIP_OVERRIDE are not used (the log says the fixed row count above is not used). --columns average is accepted but its rule is ignored: the average row length plays no part with strasser. --columns trench-edited and average-edited are refused at generate time.
  • --cell-k is read only with strasser (it must be above 0, else generate.py stops). With the default --cell-size mean it has no effect.
  • Not PTHA18's procedure. The scenarios do not match PTHA18's one by one.

When to use it

  1. With --rupture-size local. The rupture size follows the scaling relation at each place only if the cells are small enough there. The rptha rule, with one block of cells per magnitude, gives poor ruptures on arcs whose cells are still unequal.
  2. On a fan or a zone whose width changes along strike. Check step 2's log first. If the longest or widest cell is far above the cap, the cap changes the mesh.
  3. Not needed when the default cells are already close to the cap. Then the cap changes almost nothing.
python ptha_python/generate.py calabria --zone calabria2 --folder calabria2_k15 --ptha false --rupture-size local --cell-size strasser --cell-k 1.5
python calabria2_k15/steps/step_total.py

calabria is the region search term (the first argument), which selects the SLAB region. --zone calabria2 selects the zone, and its Berryman et al. (2015) end cut is applied automatically (step 1).
